# AI Test Analysis Configuration Guide

This guide explains how to configure AI-powered test analysis for your CI/CD pipeline.

## Overview

After tests run, an AI model analyzes the Robot Framework test results (`output.xml`) and posts an objective, actionable summary as a comment on the Pull Request.

## Required Configuration

### 1. GitHub Secrets

Add your LLM API key to GitHub repository secrets:

1. Go to your repository → Settings → Secrets and variables → Actions
2. Click "New repository secret"
3. Add:
   - **Name**: `LLM_API_KEY`
   - **Value**: Your Claude API key (or OpenAI key)

### 2. GitHub Variables (Optional)

Configure the LLM provider and model:

1. Go to your repository → Settings → Secrets and variables → Actions → Variables tab
2. Add these optional variables:
   - **Name**: `LLM_PROVIDER`
     - **Value**: `claude` (default) or `openai`
   - **Name**: `LLM_MODEL`
     - **Value**: Model name (optional)
       - For Claude: `claude-3-5-sonnet-20241022` (default), `claude-3-opus-20240229`, etc.
       - For OpenAI: `gpt-4` (default), `gpt-4-turbo`, `gpt-3.5-turbo`, etc.

## Supported LLM Providers

### Claude (Anthropic)
- **Provider**: `claude`
- **Default Model**: `claude-3-5-sonnet-20241022`
- **API Key**: Get from [https://console.anthropic.com/](https://console.anthropic.com/)
- **Environment Variable**: `LLM_API_KEY`

### OpenAI
- **Provider**: `openai` or `gpt`
- **Default Model**: `gpt-4`
- **API Key**: Get from [https://platform.openai.com/](https://platform.openai.com/)
- **Environment Variable**: `LLM_API_KEY`

## How It Works

1. **Test Execution**: Robot Framework tests run in the `test` job
2. **Results Extraction**: `output.xml` files are copied from the NSO container to `packages/*/tests/output.xml`
3. **AI Analysis**: The `ai-test-analysis` job:
   - Parses all `output.xml` files
   - Extracts failure information (test names, error messages, context)
   - Sends to the configured LLM for analysis
   - Receives a short, objective interpretation
4. **PR Comment**: Posts the analysis as a comment on the Pull Request

## Example Output

The AI will post a comment like:

```markdown
## 🤖 AI Test Analysis

### Overview
2 tests failed in the ACL service package, both related to configuration validation.

### Root Cause
The tests are failing because the expected ACL entry format changed but the test assertions weren't updated. The NSO service is generating correct configurations, but the test expectations are outdated.

### Next Steps
1. Update test assertions in `packages/acl-rfs/tests/acl-rfs.robot` lines 45-50
2. Verify the new ACL entry format matches the latest YANG model
3. Re-run tests to confirm fixes

---
*Generated by AI-powered test analyzer*
```

## Local Testing

Test the script locally:

```bash
# Set environment variables
export LLM_PROVIDER=claude
export LLM_API_KEY=your-api-key-here
export GITHUB_TOKEN=your-github-token  # Optional, for PR comments

# Make sure output.xml files exist
make run-tests

# Run the AI analyzer using the Makefile target
make ai-analyze-tests

# Or run the script directly
./setup/run-ai-analysis.sh
```

The script will:
1. Create a separate Python virtual environment (`venv-ai-analysis/`)
2. Install AI dependencies in the isolated environment
3. Run the analysis
4. Clean up automatically

## Troubleshooting

### No PR Comment Posted

- Verify `GITHUB_TOKEN` has write permissions
- Check that the workflow was triggered by a Pull Request
- Review the `ai-test-analysis` job logs in GitHub Actions

### API Errors

- Verify your API key is valid and has credits
- Check the rate limits for your LLM provider
- Ensure the model name is correct

### No Test Results Found

- Confirm tests ran before the AI analysis step
- Check that `output.xml` files exist in `packages/*/tests/`
- Review the `test` job logs to ensure tests completed

## Cost Considerations

- **Claude**: ~$3 per 1M input tokens, ~$15 per 1M output tokens (Sonnet 3.5)
- **OpenAI GPT-4**: ~$30 per 1M input tokens, ~$60 per 1M output tokens

Each analysis typically uses:
- Input: ~500-2000 tokens (depending on test failures)
- Output: ~200-500 tokens

Estimated cost per analysis: **$0.01 - $0.05** per run

## Security Notes

- API keys are stored as GitHub Secrets and never exposed in logs
- The script only reads test output files, not source code
- PR comments are public to repository collaborators
